# DB Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Stand up PostgreSQL + Drizzle ORM with the complete 8-table schema from the spec, migrations checked into git, a test-DB helper, and one worked-example repo (`customers`) with integration tests — so the next plan (Clerk auth + `/me/*`) can plug in without re-litigating DB setup.

**Architecture:** A local Postgres via Docker Compose for dev. Drizzle ORM with `postgres.js` driver (recommended for Bun). Schema defined in multiple TypeScript modules under `apps/api/src/db/schema/`, re-exported from a single index. Migrations generated via `drizzle-kit generate` into `apps/api/drizzle/*.sql`, committed to git, applied at boot via a programmatic migrator. Tests run against a separate DB (`novapatch_test`), apply all migrations once at test-process startup, and truncate all tables between tests for isolation. CI gets a Postgres service container so the same tests run end-to-end.

**Tech Stack:** PostgreSQL 16 · Drizzle ORM + `drizzle-kit` · `postgres.js` · Docker Compose (dev) · GitHub Actions Postgres service (CI) · `bun:test`

**Scope of this plan (explicit):**

- NOT covered (future plans): Clerk auth + `/me/*` endpoints (next plan), checkout flow, billing jobs, webhooks, seed script, additional repos.

**File responsibilities:**
- `docker-compose.yml` owns the local dev Postgres. One service, one port, one data volume. No application containers (the API runs on the host via `bun run`).
- `apps/api/drizzle.config.ts` tells `drizzle-kit` where the schema lives and where to emit migrations. That's it.
- `apps/api/src/db/index.ts` owns the connection pool. Exports a `db` singleton (for the running app) and a factory (for tests and tooling).
- `apps/api/src/db/migrate.ts` is a runnable that applies all pending migrations. Can be called from `pnpm db:migrate` (CLI) or from the test helper (programmatic).
- `apps/api/src/db/schema/*.ts` each own a cohesive bounded-context group of tables. One file per domain keeps each under ~80 lines and focused.
- `apps/api/src/repos/customers.ts` is the first repo. It demonstrates the pattern later repos will follow (thin over Drizzle, typed I/O, no surprises).
- `apps/api/test/helpers/db.ts` owns the test-side glue: URL resolution, migration apply, `resetDb()`.
- The CI workflow gets a `services: postgres` block + `DATABASE_URL_TEST` env so test commands can reach the DB.

/**
 * Build a Drizzle client from a connection string. Shared by the runtime app,
 * scripts, and the test helper. Caller is responsible for calling
 * `client.end()` on shutdown (tests typically don't bother — process exit
 * closes it).
 */
export function createDb(connectionString: string): { db: Db; client: ReturnType<typeof postgres> } {
  const client = postgres(connectionString, {
    // Reasonable pool for a Bun-based single-process API.
    max: 10,
    // Keep types simple — we decode timestamps to Date everywhere.
    onnotice: () => {},
  });
  const db = drizzle(client, { schema });
  return { db, client };
}

export { schema };

#!/usr/bin/env bun
import { drizzle } from "drizzle-orm/postgres-js";
import { migrate } from "drizzle-orm/postgres-js/migrator";
import postgres from "postgres";
import { readEnv } from "../env";

/**
 * Applies all pending migrations from apps/api/drizzle/ against the given URL
 * (or DATABASE_URL from env). Invoked by `pnpm db:migrate` and by the test helper.
 */
export async function runMigrations(connectionString?: string): Promise<void> {
  const env = readEnv();
  const url = connectionString ?? env.DATABASE_URL;
  if (!url) {
    throw new Error("DATABASE_URL is required to run migrations");
  }
  const client = postgres(url, { max: 1 });
  try {
    const db = drizzle(client);
    await migrate(db, { migrationsFolder: `${import.meta.dir}/../../drizzle` });
  } finally {
    await client.end();
  }
}

// Run when executed directly (e.g. `bun run src/db/migrate.ts` or `pnpm db:migrate`).
if (import.meta.main) {
  await runMigrations();
  console.log("migrations applied");
}

import { beforeAll, beforeEach } from "bun:test";
import { sql } from "drizzle-orm";
import { createDb, type Db } from "../../src/db";
import { runMigrations } from "../../src/db/migrate";
import { readEnv } from "../../src/env";

let cached: { db: Db; client: ReturnType<typeof import("postgres")> } | undefined;

function getTestUrl(): string {
  const env = readEnv();
  const url = env.DATABASE_URL_TEST;
  if (!url) {
    throw new Error(
      "DATABASE_URL_TEST is required for integration tests. Set it in .env (see .env.example).",
    );
  }
  if (env.DATABASE_URL && url === env.DATABASE_URL) {
    throw new Error(
      "DATABASE_URL_TEST must differ from DATABASE_URL — tests truncate tables.",
    );
  }
  return url;
}

/**
 * Returns a shared Drizzle client pointed at DATABASE_URL_TEST. Applies
 * migrations once per process. Call at the top of any integration test file
 * (via the `useTestDb()` helper below) — do NOT create your own connection.
 */
export async function getTestDb(): Promise<Db> {
  if (cached) return cached.db;
  const url = getTestUrl();
  await runMigrations(url);
  cached = createDb(url);
  return cached.db;
}

/**
 * Truncates every application table. Leaves the `__drizzle_migrations`
 * bookkeeping table alone so we don't re-migrate between tests.
 */
export async function resetDb(db: Db): Promise<void> {
  // Order matters less with CASCADE, but list children → parents to keep the
  // generated query readable.
  await db.execute(sql`
    TRUNCATE TABLE
      discount_redemptions,
      discount_codes,
      subscription_billings,
      subscriptions,
      order_items,
      orders,
      customers,
      influencers
    RESTART IDENTITY CASCADE
  `);
}

/**
 * Convenience: drop at the top of a describe() block. Handles both the
 * once-per-file migration and the per-test truncate.
 */
export function useTestDb(): { getDb: () => Db } {
  let db: Db;
  beforeAll(async () => {
    db = await getTestDb();
  });
  beforeEach(async () => {
    await resetDb(db);
  });
  return {
    getDb: () => db,
  };
}

import { eq } from "drizzle-orm";
import type { Db } from "../db";
import { customers, type Customer } from "../db/schema/customers";

export interface UpsertCustomerInput {
  clerkUserId: string;
  email: string;
}

/**
 * Idempotent upsert by clerk_user_id. If a row exists, updates `email` +
 * `updated_at` and returns it; otherwise inserts and returns the new row.
 *
 * Keyed on clerk_user_id (not email) because email can change in Clerk but
 * the Clerk user id is stable for the account lifetime.
 */
export async function upsertCustomerByClerkUserId(
  db: Db,
  input: UpsertCustomerInput,
): Promise<Customer> {
  const [row] = await db
    .insert(customers)
    .values({
      clerkUserId: input.clerkUserId,
      email: input.email,
    })
    .onConflictDoUpdate({
      target: customers.clerkUserId,
      set: {
        email: input.email,
        updatedAt: new Date(),
      },
    })
    .returning();
  if (!row) {
    throw new Error("upsertCustomerByClerkUserId returned no row");
  }
  return row;
}

export async function getCustomerById(db: Db, id: string): Promise<Customer | undefined> {
  const [row] = await db.select().from(customers).where(eq(customers.id, id)).limit(1);
  return row;
}
